# Linux viewer: чёрное окно в первых wheels

Если изображение уже есть, но звенья повёрнуты неправильно, это отдельная ошибка
импорта DAE, общая для Linux и Windows: [VIEWER_MESHES.md](VIEWER_MESHES.md).

## Причина

В Linux wheels от 2026-10-29 обнаружена ошибка упаковки OpenGL. GLFW создавал
контекст через системный `libGLX`/`libGL`, а `_viewer` вызывал функции через
добавленные auditwheel копии `libOpenGL` и `libGLdispatch`. У второго dispatch
не было текущего контекста: окно открывалось, но и сцена, и панель оставались чёрными.
Это не ошибка чтения суставов, CSV или SDK. Windows/QEMU требует своего драйвера
OpenGL; это другой случай, описанный в [DISTRIBUTION.md](DISTRIBUTION.md).

Ошибка воспроизведена с установленным wheel и внешним localhost mock:
системный `glGetString(GL_VERSION)` возвращал версию Mesa, тот же вызов через
зависимости `_viewer` возвращал `NULL`. Снимок окна содержал только чёрные пиксели.
Сборка из исходников с системными библиотеками рисовала ту же сцену нормально.

## Исправление

На Linux сборка теперь выбирает `OpenGL_GL_PREFERENCE=LEGACY`: это выбор системного
интерфейса `libGL.so.1`, а не отключение GPU или понижение версии OpenGL.
Так создание контекста и отрисовка используют один графический стек.
Семантика настройки: [CMake FindOpenGL](https://cmake.org/cmake/help/latest/module/FindOpenGL.html#hints).

Дополнительно `_viewer` проверяет видимость текущего OpenGL-контекста при создании
окна и выдаёт ошибку вместо продолжения с неработающей отрисовкой.

В Linux smoke-тесте теперь запускается именно `robot.connect(viewer=True)`
в отдельном процессе с одной/двумя mock-руками. Изображение проверяется и сохраняется
в изолированном Xvfb. Старый тест проверял только возврат `update()` и поэтому
ошибочно проходил даже при чёрном окне; ранние отчёты GUI не доказывали наличие изображения.
Проверка пикселей обнаруживает этот сбой, но не заменяет длительный визуальный тест
или проверку на всех GPU/Wayland-композиторах.

## Обновление установленного wheel

Все шесть Linux wheels пересобраны 2026-10-30. Используйте актуальные файлы и SHA256 из
[WHEEL_MATRIX.md](WHEEL_MATRIX.md). Имена и версия `0.1.0` сохранены для этой
локальной исправленной поставки, поэтому уже установленный пакет нужно заменить
принудительно. Из корня проекта, в том же venv, что использует Jupyter:

```bash
tag=$(python -c 'import sys; print(f"cp{sys.version_info.major}{sys.version_info.minor}")')
python -m pip install --force-reinstall --no-deps \
  "./wheelhouse/iimt_native-0.1.0-${tag}-${tag}-manylinux_2_39_x86_64.whl"
```

Затем перезапустите ядро ноутбука: уже загруженный C++-модуль не заменяется на лету.
Не устанавливайте wheel при активном выполнении траектории.

## Временный обход для старого wheel

На проверенном Linux окружении системный OpenGL можно загрузить раньше библиотек
wheel. Это обход, а не необходимость для исправленных файлов:

```bash
LD_PRELOAD=libGL.so.1 python -m jupyterlab
# Для обычного скрипта:
LD_PRELOAD=libGL.so.1 python your_script.py
```

Запускайте новый процесс Jupyter/ядро с этим окружением. Не добавляйте настройку
глобально в систему. После установки исправленного wheel уберите `LD_PRELOAD`.

Диагностические логи, старый чёрный кадр и изображения после исправления находятся
локально в `results/viewer-black-screen/` и `results/python-matrix/linux/*/gui/`.
